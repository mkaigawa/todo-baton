# todo-baton

todo.md の項目を選んで、隣のターミナルの入力欄へ渡すピッカー。

todo.md をテキストエディタで書き足すと自動で読み直し、選んだ項目を直前に触っていたターミナルの入力欄へ流し込む。複数行の項目は改行のまま入る。送信キーは押さないので、実行するかどうかは人が決める。

## 使い方

```bash
todo-baton open        # 分割ペインを作ってそこで常駐させる
todo-baton             # このターミナルで起動する
todo-baton --list      # 項目を一覧表示するだけ
```

## todo.md の書式

```markdown
- [] やりたいこと
続きの行はここに書く
```

`[]` `[ ]` `[x]` のいずれでもよく、`x` のときだけ完了。チェックボックス行の直後から **空行 / 見出し / 次のチェックボックス行** のどれかが現れるまでが同じ項目になる。継続行のインデントは任意。

置き場所は次の順に決まる。

1. `--file` / `BATON_FILE`
2. cwd から親方向に `<ディレクトリ名>_todo.md` (既定は対象ディレクトリの親、`BATON_DIR` で置き場所を変えられる)
3. cwd から親方向に `todo.md` `TODO.md` `Todo.md` `.baton/todo.md`
4. `~/todo.md`

いずれも無いときは 2 の位置に作る。**プロジェクト内に todo.md を作らない**のが狙いで、`~/src/mkaigawa/chat/` で起動すると `~/src/mkaigawa/chat_todo.md` を使う。`BATON_DIR=~/todos` にすれば `~/todos/chat_todo.md` になり、プロジェクトごとに別ファイルのまま一箇所へ集められる。

既に 3 の場所に `todo.md` があればそれを使い続けるので、従来の置き方は壊れない。

## キー操作

| キー | 動作 |
|---|---|
| ↑↓ / jk | 選択 |
| ⏎ | 入力欄へ送る |
| y | クリップボードへコピー |
| x | 完了 / 未完了の切り替え |
| f | 完了項目の表示 / 非表示 |
| e | エディタで開く |
| r | 再読込 |
| q | 終了 |

## バックエンド

どのターミナルへ渡すかはバックエンドが決める。起動時に環境から選び、`--backend` か `BATON_BACKEND` で固定できる。

**使う前提は cmux か tmux の中**。渡す相手が居てはじめて意味のある道具なので、どちらでもない素の端末では起動せず、cmux / tmux を促して終了する。

| 名前 | 送信先 | 判定 |
|---|---|---|
| `cmux` | 同じワークスペースで選択中のターミナル | `CMUX_SURFACE_ID` があるか、`cmux tree` が通れば |
| `tmux` | 同じウィンドウのアクティブなペイン | `TMUX` があるか、attach 済みのセッションがあれば |
| `clipboard` | クリップボード (貼るのは人) | `--backend clipboard` と明示したときだけ |

多重化ソフトの外では、別のターミナルの入力欄へ文字を入れる汎用の手段が無い。`TIOCSTI` は自分の制御端末にしか撃てず、Accessibility のキー送出は最前面のアプリにしか届かないのでどのペインかを指定できない。`clipboard` は ⏎ でクリップボードに入れるところまでをやって、貼るのは人に任せる逃げ道で、`open` は分割するペインが無いので使えない。

渡す相手が居ないぶん値打ちは薄く、普通の todo リストに近づく。だから**環境まかせでは選ばれない**ようにしてある。素の端末でうっかり起動して「ただの todo アプリ」になっているのに気づかない、という状態を作らないため。

tmux の判定が「サーバが起きていれば」ではなく「attach 済みのセッションがあれば」なのは、**誰も見ていないセッションに送っても人の目に入らない**から。ペインが見えない場所に生えて、送った項目もそこで止まる。attach 済みのセッションが複数あるときは直近に触っていたものを相手にする。

判定に「叩いて通れば」が入っているのは、cmux CLI が cmux 内で起動されたプロセス以外を拒否し、その判定が環境変数ではなくプロセスの親子関係だから。`cmux` が PATH にあるだけで選んでしまうと、素のターミナルで「アクセスが拒否されました」しか返ってこなくなる。

バックエンドが持つ責務は **送信先を決める `resolve_target()` と入力欄へ置く `paste()` の 2 つだけ**で、ピッカー本体はこの 2 つしか呼ばない。`focus()` `base_dir()` `open_pane()` と、画面を覗く `capture()`、1 回分を送る `send_text()` `send_key()` は、できるものだけが実装する任意の口。zellij や wezterm を足すときは `Backend` を継承して外部コマンドを薄く包み、`BACKENDS` に加える。

送信先の Claude Code が vim モードのとき、入力欄は送信のたびに NORMAL へ戻る。そこへ文字を流すと本文ではなく vim のコマンドとして食われ、日本語だけの行は丸ごと捨てられて**入力欄が空のまま**、英字を含む行は最初の `i` や `a` までが消えて途中から入る。一度目は入るのに二度目から入らない、という形で出る。

モード表示は NORMAL のときだけ何も出ないので、画面を見ても NORMAL と「vim モードではない」の区別がつかない。しかも見てから送るまでの間にモードは動く。だから**見て判断してから送る**と、判断が外れたときに本文が食われる。

そこで判断せず、**本文の直前に必ず `i` を打つ**。NORMAL なら INSERT に入り、INSERT なら `i` が 1 文字入るだけで、本文が届く時点では必ず INSERT になっている。余った `i` は消す。消さないのは「打つ前は表示が無く、打った後に INSERT が出た」ときだけで、これは `i` がコマンドとして食われた証拠なので入力欄には何も入っていない。相手が素のシェルでも余計な文字は残らない。

VISUAL のときは送らずに断る。`i` が文字選択の起点になってしまうし、人が入れたモードなので道具では戻さない。

画面を覗くときは**末尾の空行を捨ててから**末尾の数行を見る。履歴が短いうちは入力欄が画面の下端に無いので、素直に最後の数行を取るとモード表示ではなく空行を見て「画面が覗けない」と誤解する。

## 環境変数

| 変数 | 意味 |
|---|---|
| `BATON_FILE` | todo.md のパス (1 ファイル固定) |
| `BATON_DIR` | `<ディレクトリ名>_todo.md` の置き場所 (既定: 対象ディレクトリの親) |

## 設定ファイル

`~/.config/baton/env` (`XDG_CONFIG_HOME` を尊重) に `KEY=value` を書くと、上の環境変数の既定値になる。シェルの rc を触らずに済む。

```sh
# ~/.config/baton/env
BATON_DIR=~/todos
```

`#` で始まる行は註釈。値の引用符は剥がす。`BATON_` で始まらないキーは読まない。**環境変数が設定されていればそちらが勝つ**ので、その場だけ変えたいときは `BATON_DIR=... todo-baton` でよい。

外部ライブラリは使わない (stdlib のみ)。プロジェクト内に `.env` を置く方式は、プロジェクトを汚さない方針に反するので採らない。

## インストール

```bash
git clone git@github.com:mkaigawa/todo-baton.git
cd todo-baton
chmod +x todo-baton
mv todo-baton ~/.local/bin/
```

`~/.local/bin` が `PATH` に無ければ、シェルの rc ファイルに追加してください。

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## 要件

- Python 3.7+
- cmux または tmux
